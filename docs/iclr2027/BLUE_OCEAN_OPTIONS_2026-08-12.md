# ICLR 2027 蓝海方向重新评估（2026-08-12）

## 核心结论

目前的结果值得继续研究，但还没有识别出一个可投稿的作用机制。Poker 任务上的结果是
Action Image 组 85/100、Scene-only 组 74/100，但这个对比同时改变了两个因素：

1. 增加了一帧当前 Action Image，作为 policy 的条件输入；
2. 对未来 Action Image 帧施加了辅助视频损失。

此外，Action Image 组的视频 token 数量也是 Scene-only 组的两倍。因此，近期最稳妥的论文问题
不应该是“Action Image 是否有效”，而应该是：

> 在 World Action Model 中，Action Image 的哪一种角色真正有效：输入接口、原生视觉监督目标，
> 还是输入与目标耦合的共享通道？

宽泛的“把动作或 proprioception 表示成像素”已经不是蓝海。SelfWAM、Robot-Factored World
Models、AimBot、MV-VDP 等工作已经占据了这个叙事中的重要位置。

## 已排队的决策实验

四个实验臂都使用相同的 18 帧双 segment 输入、数据窗口、有效 batch size、优化器、学习率和
训练步数。

| 当前 Action Image 输入 | 未来 Action Image 损失 | 实验含义 | 作业 |
|---|---:|---|---:|
| 空白 | 0 | token/计算量对照 | 349065 -> 评估 349399 |
| 真实 | 0 | 仅输入 | 349070 -> 评估 349400 |
| 空白 | 0.05 | 仅目标 | 349071 -> 评估 349398 |
| 真实 | 0.05 | 输入与目标耦合 | 已有 85/100 checkpoint |

结果解释门槛：

- 仅目标组胜出：继续研究**原生视觉动作监督**。
- 仅输入组胜出：输入接口的故事仍有可能成立，但必须直接击败向量、RGB overlay、机器人渲染和
  token-matched 对照。
- 只有输入与目标耦合组胜出：研究 **input-target cycle**，并验证共享视觉坐标是否必要。
- 两个单因素组都不胜出：将 85/100 视为交互效应或架构混杂，不再包装原始创新点。

最终决定前，每个 seed 至少评估 100 个闭环 episode，并使用三个训练 seed。第一轮只用于筛选，
不能直接作为论文最终证据。

三个新训练作业使用固定输出目录，并各自连接了 100-episode 依赖评估。所有评估还依赖完整的
Poker 指令缓存作业 349393。原作业 348908/348914/348915 在启动前已取消，因为其时间戳输出目录
无法可靠地预先连接依赖评估。

## 候选研究方向排序

### 1. Visual Action 的角色因子分解（推荐的论文框架）

**研究问题。** 现有 Visual Action 工作把像素用于多种不同角色：policy 输出、world model 条件、
当前状态条件、mask 或未来辅助目标。究竟哪一种角色真正把视频预训练先验迁移到了机器人控制？

**具体贡献。** 建立一套受控实验框架，分别隔离：

1. 输入信息量；
2. token 和计算量；
3. 当前 Visual Action 条件；
4. 未来 Visual Action 监督；
5. 输入与目标使用共享坐标系还是不同坐标系。

已经排队的 2x2 实验只是第一个决策实验，不是完整研究。

**为什么可能是蓝海。** 最近的论文分别提出了不同 Visual Action 接口，但通常同时改变表示角色、
模型架构和计算量。对不同角色进行严格因果分解，是一个不同的科学贡献。即使结果否定当前的
输入接口故事，这项研究仍然有价值。

**必须获得的证据。** 在多个任务和训练 seed 上重复胜出的实验单元，并加入：

- token-matched 的 learned-image 对照；
- 向量或 SE(3) 辅助目标；
- 打乱视觉坐标的 Action Image 目标。

一篇有说服力的论文需要得到稳定结论，例如“视觉目标有效，但视觉输入无效”或“只有共享的
输入输出坐标才能产生收益”，而不是得到一张结果相互矛盾的消融表。

**第二阶段的辨识性对照，只在 2x2 之后运行：**

1. **几何干预。** 比较相机对齐正确的渲染与交换视角或固定错误相机的渲染。两者携带相同动作信息，
   token 数量完全一致，但只有前者与场景几何对齐。
2. **同信息、不同形状的对照。** 将相同的 16D 数值编码成条形图或空间位置打乱的 raster。
   这可以区分真正的视觉几何收益与“给 VAE/video 路径增加一个容易读取的冗余编码”。
3. **预训练干预。** 冻结预训练 video expert，只训练 action 侧模块。如果几何对齐的 Visual
   Action 仍然优于向量/token 对照，才能更有力地说明它复用了预训练视觉特征。如果优势只在全量
   finetune 后出现，就不能声称它直接利用了视频预训练先验。
4. **数据效率曲线。** 对胜出组和最强对照组分别使用 10%、25%、50% 和 100% demonstrations。
   如果机制确实来自预训练对齐，优势通常应该在低数据区间更加明显。

其中，几何干预和预训练干预是最低限度必须完成的一对实验。在一个 factorial seed 识别出需要解释的
角色之前，不要一次性运行全部对照。

**当前评分。** 创新性 4/5，可行性 5/5，与已有证据匹配度 5/5。主要风险是：如果没有得到明确的
因果结论，整项工作可能只像一篇诊断报告，而不像完整的 ICLR 论文。

### 2. 可控像素监督（条件成立后使用的方法）

**研究问题。** WAM 是否应该把生成能力用于预测所有未来 RGB 像素，还是应该增加一个辅助目标，
专门隔离由机器人动作控制的像素？

**具体方法。** 训练时将未来末端执行器或动作轨迹渲染到视频 latent 空间，并由预训练 video DiT
预测；推理时删除辅助分支。这里真正有意义的版本不是泛泛的“预测轨迹”，而是不用独立的数值轨迹头，
直接利用预训练视频模型原生的生成空间进行监督。

**为什么可能成立。** 它与已有正结果一致，也有清晰的机制实验。它不同于 SelfWAM 的可见机器人
self-mask，也不同于 Robot-Factored 的条件渲染。不过，MV-VDP 和 OASIS 已经让这一邻域比较拥挤。

**关键限制。** 当前仅目标组在推理时仍然处理一个空白的第二视频 segment，因此这轮实验还不能证明
部署时零额外开销。更重要的是，Action Images v1 已经把 Action Image 当成生成目标。所以，
仅目标组胜出只能提供机制证据，本身不足以构成 v2 的创新点。可部署版本需要训练时 branch dropout
或蒸馏，使推理时能完全删除辅助 segment，同时还必须放在更完整的角色因子分解研究中。

**必须获得的证据。** 仅目标组必须优于 token 对照。之后还要比较：

- 参数量匹配的 SE(3) 轨迹头；
- heatmap 辅助头；
- SelfWAM 风格的机器人 mask 监督。

至少要在三个任务和一种跨视角或跨本体分布偏移上获得收益。

**当前评分。** 单独作为创新点时为 2.5/5，可行性 5/5，与已有证据匹配度 5/5。只有 factorial
实验隔离出目标监督效应，并且辅助分支能在推理时删除，才将它作为方向 1 中的具体方法。

### 3. 相机诱导的动作几何（蓝海方法备选）

**研究问题。** 为什么对 xyz、四元数和夹爪维度进行归一化后的欧氏误差，会是从图像中学习动作分布
的正确几何？

**具体方法。** 使用可微投影器，将预测动作轨迹及其姿态基点投影到实际观测相机中。将多视角重投影
距离作为 flow matching 的辅助损失，或作为相机条件化的动作 metric。Policy 仍然输出标准 16D
动作，部署时不需要任何渲染后的动作 token。

**为什么可能成立。** Riemannian Flow Matching 使用动作空间的内在流形，一些多视角 policy 也会
预测 heatmap，但目前的检索没有发现直接使用真实观测相机来诱导 WAM/action expert 训练 metric
的方法。它的主张是损失函数和优化几何，而不是又一种像素输入接口。必须与以下方法比较：

- SE(3) geodesic loss；
- 手工逐维加权；
- 额外 MLP 辅助头。

**低成本 go/no-go 探针。** 在 held-out 动作预测上，检验多视角投影误差是否比归一化 16D MSE 和
SE(3) geodesic error 更能预测闭环失败或所需纠正幅度。同时量化具有相同 16D norm 的扰动，在
图像投影后果上有多大差异。只有这个 metric 提供了明确的新增预测信息，才进入训练。

**当前评分。** 创新性 4/5，可行性 3/5，与已有证据匹配度 3/5。它是最好的独立方法备选，但目前的
85/74 结果并不能验证它。

### 4. Action-Tube 场景学习（已筛掉）

**原研究问题。** 在没有分割和接触标签的情况下，已知未来动作轨迹是否能告诉视频 world model，
应该在哪里重点学习由动作引起的场景变化？

**原方法。** 在投影后的未来动作路径周围构造时空 tube。在排除 Action Image 本身像素后，对 tube
外围区域的未来 RGB 重建进行加权或 token routing，使模型重点学习物体响应，而不是机器人本体。

**低成本探针。** 在多个 RoboTwin 任务上，比较未来轨迹外围区域内的 RGB 时间变化能量，并使用同一
episode 的错时轨迹和“仅当前末端位置”作为对照。探针排除了末端路径的内核区域，但无法去掉所有可见
机器人像素。预设通过标准为：相对错时轨迹至少 2 倍、相对当前位置至少 1.25 倍，并且每个任务相对
错时轨迹都至少 1.5 倍。

**已完成结果。** 共覆盖 134 个 episode、1322 个窗口。真实未来轨迹区域的变化能量是错时轨迹的
1.96 倍，但只是在当前位置区域的 1.02 倍。各任务真实轨迹/错时轨迹比分别为：

- Poker：1.22；
- Place：1.44；
- Stack：2.28。

**决定。** No-go。该 tube 主要识别出“当前机器人附近的像素会移动”，未来轨迹几何几乎没有提供
额外信号。不要使用当前定义训练这个损失。

### 5. 反事实 Action-Response Grounding（科学价值高，但拥挤）

**研究问题。** 当输入反事实动作时，WAM 是否只改变真正受该动作因果影响的场景区域，同时保持其余
世界不变？

**具体方法。** 将模拟器重置到完全相同的状态，执行多个邻近 action chunk，并使用不同 Action Image
之间的差异来定位和监督场景响应差异。最终可以将一致性目标用于 policy 学习或构造反事实 verifier。

**风险。** CoCo 和 ActSWM 已经将反事实一致性或 action sensitivity 作为核心。只有 Action Image
定位能够实现这些方法无法得到的结果，例如显著减少反事实数据需求或提高接触区域准确性，才值得继续。

**当前评分。** 创新性 2.5/5，可行性 2/5，科学价值 5/5。

### 6. ActionClock / 数据时间同步（适合作为副线）

**研究问题。** 投影后的机器人运动是否能识别操作数据中的视频与动作时间戳错位？

**已完成探针。** 在 227 个注入合成时间偏移的 RoboTwin episode 上：

- 精确恢复准确率：66.1%；
- 误差不超过 1 帧：88.5%；
- 误差不超过 2 帧：95.2%。

但是简单的全局速度基线更好：精确恢复 69.6%，误差不超过 1 帧为 96.0%。

**决定。** 时间偏移确实可观测，但目前没有证据说明 Action Image 几何是关键原因。将它保留为数据质量
工具或附录。除非在真实数据集上发现系统性错位，并且纠正后相对速度基线显著提升 policy 成功率，
否则不要把它作为主论文。

**当前评分。** 创新性 3.5/5，可行性 4/5，与当前结果匹配度 2/5。

### 7. 视觉 Agency / Kinesthesia（暂时停止）

**已完成探针。** 使用 body-world motion coupling 和弱标签，检测成功 demonstration 中稳定的闭合
夹爪阶段。共覆盖 240 个 episode、11,217 个样本：

- 基础模型 AUC：0.687；
- coupling AUC：0.680；
- time-shuffled AUC：0.713。

预设通过标准是 coupling 相对两个基线都至少提高 0.10。

**决定。** 在现有标签条件下，信号为负。除非能够取得模拟器的接触/物体所有权真值，并生成受控扰动
rollout，否则不要继续投入 GPU。

## 必须引用并直接击败的近期工作

- [SelfWAM](https://arxiv.org/abs/2608.00725)：Action-conditioned FastWAM 加未来 self-mask
  监督，是架构上最接近的竞争工作。
- [Robot-Factored World Models via Robot Rendering](https://arxiv.org/abs/2607.22535)：
  使用相机对齐的机器人几何和深度作为 world model 接口。
- [Masked Visual Actions](https://arxiv.org/abs/2607.19343)：使用部分显露的像素轨迹作为跨实体
  Visual Control Interface。这使宽泛的视觉接口主张尤其危险。
- [MV-VDP](https://arxiv.org/abs/2604.03181)：同时预测多视角未来 heatmap video 和 RGB。
- [OASIS](https://arxiv.org/abs/2605.25829)：将相机坐标系下的 SE(3) 轨迹预测作为 policy 辅助监督。
- [AimBot](https://arxiv.org/abs/2508.08113)：在 RGB 观测上叠加末端执行器空间提示。
- [PointWorld](https://arxiv.org/abs/2601.03782)：跨本体的 3D point-flow 动作/世界接口。
- [CoCo](https://arxiv.org/abs/2608.04653)：面向 action-controllable world model 的反事实一致性。
- [ActSWM](https://arxiv.org/abs/2607.26712)：action-sensitive world modeling。

## 论文级决策标准

在 2x2 结果出来前，不要确定论文标题或 headline。一篇站得住的 ICLR 投稿至少需要满足：

1. 在 token-matched 条件下隔离出一个可重复产生 policy 收益的因果因素。
2. 使用携带相同信息的数值表示作为对照，而不是只比较 Scene-only 与更多输入。
3. 使用与核心主张对应的机制指标，例如接触区域预测、action sensitivity 或监督效率，不能只有成功率。
4. 至少三个操作任务、三个训练 seed，以及一种有意义的分布偏移。
5. 直接比较最接近的 2026 年工作，不能依赖宽泛的“模态鸿沟”叙事。

当前最高价值的执行顺序是：先完成 2x2 筛选，将其结果组织成 Visual Action 角色因子分解；然后再根据
结果选择具体方法。Action-Tube 探针已经没有通过门槛。相机诱导的动作几何是最好的独立备选，但在投入
训练之前，必须先通过离线 metric 探针。
