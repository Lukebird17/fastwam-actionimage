## 0. 三十秒版本（电梯陈述）

> 现在的 World Action Model（WAM）把机器人的本体感觉（proprioception）压成一个低维向量
> token 喂给动作模块——**它进不了视频骨干的视觉先验**。我们换一个做法：把 proprio **渲染成
> 一张图像**，当作一帧条件图注入预训练视频骨干。在 RoboTwin 双臂任务上，仅改这一个表示，
> 成功率从 0.74 → 0.85（100 集，配对检验 p=0.035，显著）。
>
> 这是对社区刚命名的开放问题（"VLA 该怎么用 proprioception?",arXiv 2608.03052）给出的
> 一个**像素空间的答案**——而那篇综述枚举的 5 种接口里，没有一种是像素级的。

## 1. 我们到底在解决什么问题

### 1.1 大背景（为什么现在做这个）

机器人学习正在经历"视频生成当世界模型"的范式转移。FastWAM(arXiv 2603.16666）刚证明了一
个反直觉的结论：**WAM 在推理时不需要真的去"想象"未来视频——训练时的视频协同训练才是关键**。
于是推理时视频 DiT 退化成一个"世界编码器",action expert 直接出动作，又快又强。

### 1.2 但 FastWAM 留下了一个没被解决的模态鸿沟

视频骨干是在海量自然视频上预训练的，它的**视觉先验全在像素空间**。而机器人自己的状态
(7/16 维关节角、末端位姿）是个**低维向量**。FastWAM 的做法是把这个向量过一个 `Linear` 层
变成一个 token，拼到文本序列里喂给 action expert。

**问题：这个向量 token 和视频骨干的视觉先验是"两种语言"。** 视频骨干见过无数只手在画面里
移动，但它从来没见过一个 16 维向量。低维 token 绕开了视觉先验，白白浪费了预训练。

### 1.3 我们的答案：把 proprio 翻译成视频骨干的"母语"——像素

> **把当前 proprio 渲染成一张语义图像（action image)，当作一帧条件图 pin 进视频 latent 序列。**

这样一来，机器人自己的身体状态也变成了"一帧画面"，能直接被视频骨干的视觉先验处理。
模态鸿沟不是用更复杂的融合模块去"桥接"，而是在**表示层直接抹平**——状态本来就是图像，
不需要桥。

### 1.4 为什么这个问题是被社区"认证"过的真问题

- **arXiv 2608.03052**(2026-08)《How Should VLAs Use Proprioceptive State?》系统比较了
  proprio 注入的 **5 种接口**:state prompt / VLM prefix / action prefix / state expert /
  feature modulation。**没有一种是"渲染成像素帧进视频骨干"。** 它证明了两件事：
  (1) 这个问题现在是被认真对待的开放问题；(2) 像素空间这个答案还空着。
- **GeoProp(arXiv 2607.07101)** 是最接近的工作：它把 state 投影到图像平面，但只在
  **特征空间**做 FiLM 调制（在投影位置采样局部视觉特征）,**不是像素级条件帧，也不进视频扩散骨干**。

**一句话：问题是被认证的，像素空间答案是真空白。**

## 2. 核心创新点（焊死版）

### C1【主打，唯一 headline】Proprioception-as-Image 作为条件接口

**主张**：把机器人本体感觉渲染回像素空间，作为预训练视频骨干的条件帧，让动作状态也能
吃到视觉先验。

**三个支撑论点**:
1. **表示对齐**：像素是视频骨干的母语。渲染成图像 = 状态进入视觉先验，向量 token 不行。
2. **双向使用，天然闭环**:Action Images v1 证明 action 可以"被生成"（输出端）;
   本工作证明 action 可以"被渲染回来做条件"（输入端）。**同一表示，双向可用**——这是闭环
   replan 的天然机制：每 32 步把当前 proprio 重渲染成新条件帧，出下一个 action chunk。
3. **直接回应 v1 自认的 limitation**:v1 原文写"not yet been fully developed into a
   closed-loop policy"。本工作正是把它闭环化。

**为什么是新内容而不是 v1 重炒**:v1 里 action image 是**生成目标**（模型要画出 action image
再解码成动作）；本工作里 action image 是**条件接口**（模型不生成它，而是把它当输入）。角色完全
反过来，且首次放进了 FastWAM 这种"推理不生成视频"的 WAM 范式。

### C2【副贡献，但已弱化】向视频 DiT 注入干净条件帧的关键实现

把一帧干净（无噪声）条件图注入视频 DiT，需要正确处理三件事。**真实消融结果（2026-08-10）**:

| 实现细节 | off 组成功率 | on 组（参照 0.84) | 判定 |
|---|---|---|---|
| **pin 位置**:RoPE 把 latent 帧索引编码进 Q/K，条件帧必须 pin 在训练时见过的位置 | 0.10（错位） | 0.82（对齐） | ✅ **必要条件，错位即崩** |
| t=0 时间标记：显式给干净帧打 per-token t=0 | 0.88 | 0.84 | ❌ 非必要（off 反略高，p=0.75 不显著） |
| 注意力隔离：条件帧 causal 隔离，防未来噪声污染 | 0.78 | 0.84 | ⚠️ 方向对但 n=50 测不出（p=0.58) |

**诚实结论：C2 不能写成"三个必要条件"。** 只有 pin 位置被数据明确证实。所以 C2 降级为：
- **主呈现**:"pin 位置是注入干净条件帧的关键，错位会让闭环性能从 0.82 崩到 0.10"——
  这是一个有实操价值的 finding（很多人复现时会踩这个坑）。
- **负结果也是贡献**：诚实报告 t=0/isolation 在本设定不显著，反而显得严谨。
- **红线**:t=0 标记的机制**早已被 Diffusion Forcing(arXiv 2407.01392）提出**。
  我们**绝不声称首次发现**,related work 显眼引用。

### C3【支撑结果，非头条】双臂 16D / RoboTwin-50 / Aloha-Agilex 扩展

- v1 是 7-DoF 单臂 RLBench；本工作是 **16D 双臂、50 任务**。
- 价值：证明 action image 表示能迁移到双臂多任务 regime。
- **定位约束**：双臂视频生成已被 CRAFT(2604.03552）等占，所以 C3 只当"扩展证据"，
  不当创新点写。

### 明确放弃的方向（红海，不写进贡献）

- ❌ "跳过 test-time imagination"—— UVA(2503.00200）比 FastWAM 更早，已是红海子领域。
- ❌ latent-action 世界模型 —— DLAM/WALA/LaWAM 红海，且核心代码未实现。
- ❌ 不确定性/何时 replan —— 2026-08 刚被 GUARD/SAFECAST 等占。
- ❌ 触觉/音频新模态 —— 触觉已 6 篇，音频虽空但 RoboTwin 仿真音频真实性是致命前提。

## 3. 实验证据链（真实数据，已全部跑完）

### 3.1 主对比(C1 的根基)— 已显著 ✅

| 臂 | 表示 | 100 集成功率 | 配对统计 |
|---|---|---|---|
| ① 纯 FastWAM | proprio → Linear → 向量 token | 0.74 (74/100) | — |
| ② +ActionImages | proprio → **渲染成图像 → 条件帧** | **0.85 (85/100)** | **McNemar p=0.035** |

**公平性（关键）**：两臂拿到**完全相同的 16D proprio**（同一数据管线、同 545 episodes、
同 46752 windows、同归一化、同文本缓存），唯一区别是 ②额外把同一个 proprio 渲染成图像当条件帧。
**这是"像素空间 vs 向量空间"的干净单变量对比**——信息完全同源，只是表示形式不同。

**显著性历程**:50 集时 0.84 vs 0.72,McNemar p=0.21（不显著）→ 加量到 100 集后 p=0.035
跨过显著线。验证了"必须加量"的判断。**仅②能解决的 episode 有 17 个，仅①的只有 6 个。**

### 3.2 机制消融（C2)— pin 站得住，另两条弱化

见 §2 C2 表格。核心 takeaway:**pin 位置是关键实现细节**(0.82 vs 0.10)，其余两条在本设定
不显著。

### 3.3 多任务 scaling(C3)— 支撑证据

③ 全任务（50 任务）训到 step_125000(~1.5 epoch)。其角色是证明 action image 在多任务 regime
仍有效，不追求单任务 SOTA。**当前评估是欠训状态下的数字，不能直接与单任务臂比。**
